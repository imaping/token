# 如何在其他项目中使用 imaping-token

本文档说明如何在你的项目中引用已经发布到 Maven Central 的 `imaping-token` 组件。

## 前置条件

- Maven 3.9 及以上
- JDK 17 及以上
- 可以访问 Maven Central 或团队内部镜像

## 使用方式

发布到 Maven Central 后，默认不需要额外配置私有仓库，也不需要 GitHub Token。

### 方式 1：直接按模块引用

```xml
<dependencies>
    <dependency>
        <groupId>io.github.imaping</groupId>
        <artifactId>imaping-token-api</artifactId>
        <version>1.3.2</version>
    </dependency>

    <dependency>
        <groupId>io.github.imaping</groupId>
        <artifactId>imaping-token-resource-client</artifactId>
        <version>1.3.2</version>
    </dependency>
</dependencies>
```

如果你需要 Redis 注册表实现，可以额外引入：

```xml
<dependency>
    <groupId>io.github.imaping</groupId>
    <artifactId>imaping-token-redis-registry</artifactId>
    <version>1.3.2</version>
</dependency>
```

### 方式 2：先引入 BOM，再省略模块版本号

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>io.github.imaping</groupId>
            <artifactId>imaping-token-dependencies</artifactId>
            <version>1.3.2</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>io.github.imaping</groupId>
        <artifactId>imaping-token-api</artifactId>
    </dependency>
    <dependency>
        <groupId>io.github.imaping</groupId>
        <artifactId>imaping-token-resource-client</artifactId>
    </dependency>
</dependencies>
```

## 常用模块

- `imaping-token-dependencies`：BOM，统一管理版本。
- `imaping-token-configuration-model`：配置模型。
- `imaping-token-core`：核心抽象与基础能力。
- `imaping-token-api`：Token API 与注册表能力。
- `imaping-token-redis-registry`：Redis 注册表实现。
- `imaping-token-resource-client`：Spring Security 资源端集成。

## 验证依赖

```bash
mvn dependency:tree
```

如果依赖已经同步到 Central，命令会正常解析并下载相关组件。

## 常见问题

### 1. 无法下载依赖

排查顺序：

1. 确认版本号已经实际发布到 Maven Central。
2. 检查本机或公司 Maven 镜像是否同步了对应版本。
3. 执行 `mvn -U dependency:tree` 强制刷新本地缓存。

### 2. 公司内网只能走私服

如果你所在环境只能通过 Nexus/Artifactory 访问依赖，需要让私服代理 Maven Central，或者先将对应版本同步到内部仓库。
